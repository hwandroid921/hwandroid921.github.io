관광지 탐색 → 회원 인증 → 리뷰 작성 → 게시판 문의

온라인 서점 ReadMe

도서 조회, 장바구니, 주문과 주문 내역으로 이어지는 구매 과정을 구현한 온라인 서점입니다.

담당 작업
Vue 3 화면 구현과 Pinia 상태 관리를 중심으로 구매 과정 구성
확인된 기술
Vue 3, Pinia

요구사항

사용자가 도서를 조회하고 상세 정보를 확인한 뒤, 장바구니와 주문 과정을 거쳐 주문 내역을 확인할 수 있어야 합니다.

  • 도서 목록 및 상세 조회
  • 장바구니와 주문·결제 흐름
  • 주문 내역 확인

방법 및 기술 스택

Vue 3로 구매 단계별 화면을 구성하고 Pinia로 상태를 관리했습니다. 화면 단위 상태와 요청 흐름을 분리해, 장바구니에서 주문으로 이어지는 과정을 정리했습니다.

도서 조회 → 상세 확인 → 장바구니 → 주문 → 주문 내역

트러블슈팅 및 문제 해결

장바구니와 주문 단계의 상태 분리
문제
구매 과정에서는 화면 상태와 요청 흐름이 섞이지 않도록 관리해야 했습니다. 특히 장바구니에서 주문으로 이동하는 단계가 주요 고려 사항이었습니다.
접근
Vue 3 화면과 Pinia 상태 관리를 바탕으로 화면 단위 상태와 요청 흐름을 분리했습니다.
구현 내용
도서 탐색, 장바구니, 주문 및 내역 확인을 구매 순서에 맞게 구성했습니다.

LogMile

주행 상태를 수집하고 이상 상태를 판단해, 화물차 운전자 피로도를 모니터링하는 플랫폼입니다.

담당 작업
상태 데이터 흐름과 모니터링 화면 연결, 백엔드와 AI 분석 API 연동 구조 정리
확인된 기술
FastAPI 연동

요구사항

수집한 주행 상태를 분석하고, 판단 결과를 모니터링 화면에서 이해할 수 있는 정보로 제공해야 합니다.

  • 주행 상태 데이터 수집
  • 이상 상태 판단과 AI 분석 API 연동
  • 모니터링 화면을 통한 결과 확인

방법 및 기술 스택

데이터 수집, 분석과 화면 표시를 나누어 흐름을 구성했습니다. FastAPI 연동을 포함한 백엔드·AI 분석 API 구조를 정리하고, 상태 데이터와 모니터링 화면을 연결했습니다.

상태 수집 → 이상 판단 및 분석 → 모니터링 → 결과 확인

트러블슈팅 및 문제 해결

분석 결과를 모니터링 정보로 전달
문제
상태 데이터를 수집하는 것만으로는 사용자가 판단 결과를 이해하기 어렵습니다. 분석 과정과 화면 표시를 연결해야 했습니다.
접근
수집, 분석, 표시 단계를 구분하고 각 단계의 데이터 흐름을 정리했습니다.
구현 내용
주행 상태 수집부터 이상 상태 판단과 결과 확인까지 모니터링 흐름을 구성했습니다.

TokenMonitor

여러 AI 개발 도구의 플랜, 잔여 사용량과 초기화 시간을 한 화면에서 확인하는 개인용 대시보드입니다.

담당 작업
개인 사용 흐름 정의, 도구별 상태를 비교할 수 있는 UI 구성
실행 환경
Windows 데스크톱
표시 대상
ChatGPT, Claude, Antigravity

요구사항

여러 도구의 사용량 확인 화면을 각각 방문하지 않고도 주요 상태를 비교할 수 있어야 합니다.

  • 도구별 플랜과 잔여 사용량 표시
  • 초기화 시간과 상태 갱신
  • 사용량 확인 링크 연결과 Windows 실행

방법 및 실행 환경

개인적으로 필요한 사용량 확인 흐름에서 출발해 도구별 상태를 대시보드에 모았습니다. Windows 화면에서 플랜, 잔여 사용량과 초기화 시간을 비교하고 갱신하거나 관련 링크로 이동하도록 구성했습니다.

도구별 사용량 확인 → 상태 비교 → 갱신 및 외부 링크 이동

트러블슈팅 및 문제 해결

흩어진 AI 도구 사용량 정보 통합
문제
AI 도구마다 사용량 확인 위치가 달라 잔여 사용량과 초기화 시간을 한 번에 비교하기 어려웠습니다.
접근
도구별 주요 상태를 같은 대시보드에서 확인할 수 있도록 UI를 구성했습니다.
구현 내용
사용량, 초기화 시간과 확인 링크를 한 화면에서 다루는 개인용 Windows 도구를 구현했습니다.
