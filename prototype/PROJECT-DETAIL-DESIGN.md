# 프로젝트 상세 페이지 설계와 시안

작성일: 2026-10-10. React 변환 전 정보 구조와 화면 동선을 검토하는 HTML·CSS·JavaScript 시안입니다. 배포용 루트 파일은 변경하지 않습니다.

## 설계 방향

메인은 프로젝트의 성격과 본인 담당 영역을 빠르게 훑는 페이지입니다. 상세는 채용 담당자와 기술 면접관이 구현 역량을 확인하는 페이지입니다. 기존 Pretendard, 청색 강조, 네이비 본문을 유지하며 이미지를 크게 보여준 뒤 문서형 본문으로 이어집니다. 시각적 변화 4/10, 움직임 2/10, 정보 밀도 4/10을 기준으로 자동 애니메이션은 넣지 않았습니다.

기존 화면은 메인 아래에 네 프로젝트의 상세 설명을 모두 나열했습니다. 시안에서는 해당 내용을 별도 상세 화면으로 옮겼고 메인의 이미지·제목·상세 보기에서 이동합니다. 메인에는 서비스 요약과 담당 초점만 남겨 전체 페이지 길이를 줄입니다. 프로필, 학습·활동, 기술 역량, 교육과 연락처는 유지합니다.

## 페이지 구조와 동선

프로토타입은 단일 HTML 진입점 규칙에 따라 `index.html?project=bookstore` 같은 쿼리로 상세 화면을 선택합니다. 조회 매개변수가 없으면 메인입니다. 기존 `#bookstore` 링크는 상세 화면 링크로 바꾸었습니다. 잘못된 프로젝트 값은 오류 안내와 목록 복귀 링크를 보여줍니다. 전체 프로젝트와 다음 프로젝트로 이동할 수 있고 브라우저의 뒤로 가기도 사용할 수 있습니다.

| 메인에 남길 내용 | 상세에 담을 내용 |
| --- | --- |
| 대표 이미지, 프로젝트명 | 큰 대표 화면과 서비스 소개 |
| 서비스 목적 한 문단 | 요구사항과 사용자 흐름 |
| 본인이 맡은 핵심 영역 | 담당 범위와 확인된 기술 |
| 상세 보기 | 구현 방법, 문제·접근·구현 내용 |
|  | GitHub와 대표 화면 원본 |

상세는 소개 → 프로젝트와 역할 → 요구사항 → 구현 흐름 → 문제와 접근 → 관련 자료 순서입니다. 메인과 동일한 프로필 사이드바, 밝은 배경, 본문 폭과 빠른 메뉴를 유지합니다. 상세 목차는 대표 이미지 아래 본문 상단에 배치합니다. 제목 크기와 구분선은 메인 스타일을 따르며 별도의 상단 헤더나 상세 전용 다크 모드는 사용하지 않습니다. 모바일에서는 메인의 반응형 배치를 그대로 사용합니다. 인쇄 버튼은 공통 사이드바의 버튼을 사용합니다.

## 프로젝트별 서술 초점

| 프로젝트 | 메인 요약 방향 | 상세에서 설명할 역량 |
| --- | --- | --- |
| 제주 문화관광 | 관광 정보 탐색과 사용자 참여 서비스 | 인증·게시글·리뷰의 화면/API 및 저장 흐름 연결 |
| ReadMe | 도서 탐색에서 주문 내역까지 이어지는 서점 | Vue 3 화면과 Pinia 상태 관리, 구매 단계 연결 |
| LogMile | 주행 상태와 이상 판단을 확인하는 모니터링 | 상태 수집·분석·표시의 연결과 FastAPI 연동 |
| TokenMonitor | AI 도구 사용량을 비교하는 Windows 도구 | 개인 요구에서 출발한 UI 구성과 상태 비교·갱신 흐름 |

기존 상세 설명을 데이터 파일로 추출해 사용했습니다. 팀 규모, 기간, 기여율, 성능 개선 수치, 구체적인 오류 원인은 근거가 없어 추가하지 않았습니다. 기존 문서의 일반적인 설계 고민을 실제 장애 해결 사례로 과장하지 않도록 화면 제목을 ‘문제와 접근’으로 정했습니다.

## React 전환 설계

React 프로젝트 구성은 이번 작업에 포함하지 않습니다. 기존에 발견된 루트 하위 `hwandroid/` 앱도 변경하지 않습니다. 실제 전환은 `prototype/` 내부에서 진행합니다.

| 예정 컴포넌트 | 역할 |
| --- | --- |
| `ProjectSummaryCard` | 이미지·서비스 요약·담당 초점·상세 링크 |
| `ProjectDetailPage` | 프로젝트 ID 조회와 전체 상세 조합 |
| `ProjectHero` | 제목·소개·대표 화면·저장소 링크 |
| `ProjectSectionNav` | 목차와 현재 읽는 위치 표시 |
| `ProjectOverview` | 담당 역할과 확인된 기술 |
| `ProjectFlow` | 순서가 있는 사용자 흐름 |
| `ProjectDecision` | 문제·접근·구현 내용 |
| `ProjectResources` | 검증 가능한 코드·자료 링크 |
| `ProjectNavigation` | 목록 복귀와 다음 프로젝트 |

`project-data.js`의 배열은 전환 시 `src/data/projects.ts`로 옮깁니다. ID, 제목, 요약, 담당 정보, 요구사항, 구현 설명, 흐름, 문제 해결 설명, 이미지와 저장소 URL을 하나의 데이터로 관리하며 요약과 상세가 같은 데이터를 사용하도록 합니다. 현재는 정적 로컬 데이터이므로 로딩 UI가 필요하지 않습니다. 향후 API로 가져오면 로딩·조회 실패·프로젝트 없음 상태를 각각 구현합니다.

실제 React 라우터를 도입할 때는 `/projects/:projectId`를 제안합니다. 경로를 확정한 뒤 배포의 SPA 새로고침 처리와 이전 쿼리 URL의 호환을 함께 결정합니다. 인쇄는 별도의 상태 없이 클릭 이벤트로 처리합니다. 문서 제목·설명은 프로젝트별로 갱신하고, 검색 노출이 필요하면 프리렌더링을 별도로 검토합니다.

## 공개 전 보완할 증빙

현재 시안은 기존 포트폴리오 내용만 재배치했습니다. 포트폴리오 본문을 더 구체적으로 만들려면 아래 자료를 프로젝트별로 확인합니다. 확인 전에는 성과처럼 표시하지 않습니다.

- 팀 구성·개발 기간·본인 담당 기능을 확인할 README 또는 작업 기록
- 본인 코드와 연결되는 파일 경로, 커밋 또는 PR
- 실제 문제의 재현 조건, 원인, 선택한 해결 방법과 다른 선택지를 배제한 이유
- 수정 전후의 화면·응답·테스트 결과와 확인 방법
- 아키텍처/API 흐름도와 추가 화면의 출처

ReadMe는 장바구니에서 주문으로 넘어갈 때 어떤 상태를 어디에 보관했는지, LogMile은 AI 분석 API의 요청·응답이 어떤 화면에 연결됐는지를 보완하면 담당 역량이 더 명확해집니다. 제주 프로젝트는 인증과 작성 권한, TokenMonitor는 도구별 데이터 확인·갱신 방법과 실패 처리를 실제 코드에 맞춰 설명합니다.

## 시안 확인

저장소 루트에서 `node prototype/tools/preview-v7.cjs`를 실행합니다.

- 메인: `http://127.0.0.1:8767/`
- 제주: `http://127.0.0.1:8767/?project=jeju`
- ReadMe: `http://127.0.0.1:8767/?project=bookstore`
- LogMile: `http://127.0.0.1:8767/?project=logmile`
- TokenMonitor: `http://127.0.0.1:8767/?project=tokenmonitor`

확인할 동선은 메인 → 상세 → 다음 프로젝트 → 전체 프로젝트입니다. 좁은 화면의 가로 넘침, 키보드 탐색, 인쇄와 잘못된 ID도 확인합니다. 메인 반영은 별도 요청 후 진행합니다.
