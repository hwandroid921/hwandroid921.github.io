유환희의 Java/Spring Boot 백엔드 및 풀스택 웹 개발자 지원을 위한 문서 모음입니다.

- [이력서 양식](resume-templates.md)
  - 백엔드 지원용
  - 풀스택·SaaS 지원용
- [공통 자기소개서](common-cover-letter.md)
  - 직무 선택과 지원동기
  - 기술적 문제 해결
  - 협업

  - 학업 중단과 이후의 준비
  - 입사 후 포부

  - 평행
  - 대상정보기술
  - 메가스터디교육
  - 캐스트이즈
- [지원 전 점검표](application-checklist.md)

## 사용 순서

1. `resume-templates.md`에서 지원 직무에 맞는 이력서 원본을 선택한다.
2. 공고의 주요업무·자격요건·우대사항에서 핵심 단어를 3개씩 추출한다.
3. `common-cover-letter.md`에서 회사가 요구하는 문항에 맞는 소재를 선택한다.
4. `job-specific-cover-letters.md`를 참고해 회사별 지원동기와 예상 문항을 작성한다.
5. `application-checklist.md`로 사실관계, 링크, 파일명을 점검한 뒤 PDF로 제출한다.

## 작성 원칙

- 팀 전체 구현과 본인 구현을 구분한다.
- 측정하지 않은 성능 수치나 확인하지 않은 사용자 수는 작성하지 않는다.
- 기술을 나열하기보다 사용 목적, 본인의 행동, 검증 결과를 작성한다.
- 학위 취득 시점이 확정되기 전에는 임의의 졸업예정일을 기재하지 않는다.
- `[확인 필요]`, `[측정 후 입력]` 표시는 제출 전에 반드시 실제 정보로 교체한다.

## 지원 포지셔닝

기본 포지셔닝은 다음과 같다.

> Java/Spring Boot를 중심으로 REST API와 데이터베이스를 구현하고, Vue·React로 사용자 화면까지 연결할 수 있는 주니어 웹 개발자

백엔드 공고에서는 LogMile을 첫 번째 프로젝트로, 풀스택·SaaS 공고에서는 ReadMe를 첫 번째 프로젝트로 제시한다.

## 관리 기준

- 공고 정보는 지원 직전에 원문에서 마감일과 자격요건을 다시 확인한다.
- 제출본은 회사별 디렉터리 또는 별도 파일로 복사해 원본을 보존한다.
- 면접에서 설명할 수 없는 문장은 이력서와 자기소개서에 넣지 않는다.
