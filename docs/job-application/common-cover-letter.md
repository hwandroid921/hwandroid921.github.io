# 공통 자기소개서

아래 여섯 문항을 각각 500~700자로 완성해 두고, 회사가 요구하는 문항에 맞춰 조합한다.

## 1. 직무 선택과 지원동기

### 문항

> 웹 개발 직무를 선택한 이유와 해당 직무를 위해 준비한 경험을 구체적으로 작성해 주세요.

### 초안

고등학생 때 사용자의 행동에 따라 기능과 화면이 달라지는 프로그램에 관심을 가지면서 개발을 접했습니다. 대학에서 게임공학을 공부한 뒤 진로를 구체화하는 과정에서, 사용자의 문제를 기능으로 해결하고 지속적으로 개선할 수 있는 웹 서비스 개발을 직무로 선택했습니다. 이후 부트캠프에서 Java, Spring Boot, Vue, PostgreSQL을 학습하고 여러 프로젝트를 수행했습니다.

특히 LogMile 프로젝트에서는 팀장과 백엔드 개발을 맡아 JWT 인증, 운행 기록, 피로도 계산, FastAPI 기반 번호판 인식 연동을 구현했습니다. 이 경험을 통해 화면 구현뿐 아니라 데이터의 정확성, 예외 처리, 서비스 간 연동이 안정적인 서비스에 중요하다는 점을 배웠습니다. 앞으로도 Java와 Spring Boot를 중심으로 사용 가능한 기능을 안정적으로 구현하는 개발자로 성장하고자 합니다.

### 회사별 수정 지점

- 첫 문단은 공통으로 사용한다.
- 마지막 문단에 회사 서비스와 공고의 주요업무를 연결한다.
- 회사명만 바꾸는 형태의 지원동기는 사용하지 않는다.

## 2. 기술적 문제 해결

### 문항

> 프로젝트에서 발생한 기술적 문제를 분석하고 해결한 경험을 작성해 주세요.

### 작성 틀

```text
[프로젝트]에서 [구체적인 문제]가 발생했습니다.

처음에는 [초기 추정]으로 판단했지만,
[로그·재현·데이터 확인]을 통해 실제 원인이
[확인한 원인]임을 파악했습니다.

이를 해결하기 위해 [구현 또는 수정]했고,
[테스트·측정 방법]으로 정상 동작을 검증했습니다.

그 결과 [수치 또는 확인된 변화]를 얻었습니다.
이 경험을 통해 [직무와 연결되는 교훈]을 배웠습니다.
```

### 후보 소재

- GPS 기록의 중복·누락·역순 입력
- 피로도 계산 로직의 경계값
- Spring 서버와 FastAPI OCR 서버의 실패 처리
- 쇼핑몰 주문·결제 과정의 중복 요청
- AI 서비스별 응답 형식 정규화

## 3. 협업 경험

### 문항

> 팀 프로젝트에서 의견 차이나 일정 문제를 해결한 경험을 작성해 주세요.

### 작성 틀

```text
2인 팀으로 LogMile을 개발하면서 팀장과 백엔드 개발을 맡았습니다.

프로젝트 중 [API 명세 변경·일정 지연·역할 충돌] 문제가 발생했습니다.
먼저 [각 구성원의 상황과 문제]를 확인했습니다.

이후 기능을 필수·개선 항목으로 나누고,
API 요청·응답 예시와 완료 기준을 문서화했습니다.
진행 상황은 [GitHub·Notion·회의]를 통해 공유했습니다.

그 결과 [확인 가능한 협업 결과]를 얻었습니다.
이를 통해 협업에서는 완료 기준과 변경 내용을
명확하게 공유하는 것이 중요하다는 점을 배웠습니다.
```

## 4. 강점과 보완점

### 문항

> 본인의 강점과 보완해야 할 점을 개발 경험과 함께 설명해 주세요.

### 초안

저의 강점은 기능이 정상적으로 실행되는지만 확인하지 않고 예외 상황과 사용자의 이용 흐름까지 점검하는 점입니다. 프로젝트에서 명확한 안내 없이 화면이 멈추는 경우, 모바일 화면의 입력 요소가 어긋나는 경우, 버튼을 반복해서 눌렀을 때 요청이 중복되는 경우 등을 확인하며 데이터가 정확하게 저장되고 전달되는지도 함께 살펴보았습니다.

반면 세부적인 완성도에 집중해 전체 일정을 놓치는 경우가 있었습니다. 이후 기능을 필수·개선·선택 항목으로 구분하고, 핵심 기능을 먼저 안정적으로 완료한 뒤 개선하는 방식을 적용하고 있습니다. 꼼꼼함은 유지하되 일정과 협업의 균형을 고려하는 개발자가 되고자 합니다.

## 5. 학업 중단과 이후의 준비

학력 관련 문항이 있거나 면접에서 설명을 요구할 때 사용한다.

### 문항

> 학업 및 진로 과정에서 경험한 변화와 이후의 준비 과정을 작성해 주세요.

### 초안

대학에서 게임공학을 공부하며 프로그래밍을 접했지만, 진로를 구체적으로 정하지 못한 시기를 보내면서 학업을 마치지 못했습니다. 이후 여러 진로를 검토하는 과정에서 제가 지속적으로 관심을 갖는 분야가 소프트웨어 개발이라는 점을 확인했습니다.

이를 계기로 부트캠프에 참여해 Java, Spring Boot, Vue, PostgreSQL을 체계적으로 학습하고 팀 프로젝트와 개인 프로젝트를 진행했습니다. 현재는 프로젝트 경험을 취업으로 연결하는 동시에 전적대 이수학점을 활용한 학사학위 취득 계획도 준비하고 있습니다. 학업 중단 경험을 단순한 공백으로 남기지 않고, 개발 직무를 명확히 선택하고 실행하는 계기로 만들고 있습니다.

## 6. 입사 후 포부

### 문항

> 입사 후 어떤 방식으로 조직과 서비스에 기여하고 싶은지 작성해 주세요.

### 초안

입사 초기에는 회사의 서비스 도메인과 코드 규칙, 배포 및 협업 절차를 빠르게 익히겠습니다. 작은 기능 개선과 버그 수정부터 정확하게 수행하고, 변경 내용을 테스트와 문서로 남겨 팀원이 확인할 수 있도록 하겠습니다.

이후에는 Spring Boot와 데이터베이스 경험을 바탕으로 API와 데이터 처리 업무에 안정적으로 기여하고 싶습니다. 장기적으로는 백엔드와 프론트엔드의 연결 구조를 이해하는 강점을 활용해 요구사항 분석부터 구현, 배포 후 문제 확인까지 책임질 수 있는 개발자로 성장하겠습니다.

## 제출 전 검증

- 실제 경험과 본인의 담당 범위가 일치하는가?
- 상황, 행동, 결과가 구분되어 있는가?
- 결과를 확인한 방법이 포함되어 있는가?
- 지원 회사의 서비스나 업무가 최소 한 번 구체적으로 등장하는가?
- 추상적인 성격 설명이 프로젝트 행동으로 증명되는가?
